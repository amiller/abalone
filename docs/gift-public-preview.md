# Gift to first private inference public preview

Coordinated Abalone/dsmack release contract, 10 October 2026. This is acceptance
for a deployable public preview, not a claim that a release is ready today.

The [initial incognito gift trial](coupon-first-use.md) is a narrower milestone:
Abalone source can be public while the issuer service remains closed. Funded
deposit settlement and an independently operated issuer are not prerequisites
for that initial trial. Its genuine issuer/model admission and signed staging
limits still apply. The full funded/private acceptance below remains open.

Current public work belongs in the [Abalone backlog](https://github.com/amiller/abalone/issues).
The prior Abalone/dsmack milestone and issue numbers belong to historical private
planning; they are not public acquisition links or friend setup requirements.

## Success for the recipient

Andrew sends a funded gift code or link. A friend starts with a supported machine
and an operator-provisioned incognito environment, follows public instructions,
claims a private provider
credential and completes a useful inference task. No existing account, prior
pairing, funded wallet, gas purchase, private setup material or maintainer rescue
is required. Coupon possession authorizes the first claim; locally generated
recipient keys become atomically bound to it. Subsequent use authenticates that
identity. A copied gift cannot be rebound after claim; pre-claim theft/forwarding
risk must be explicit. Accountless entry does not remove service authentication.

## Required gates

1. **Public acquisition:** reviewed source, licensing, security/contribution contacts
   and versioned installation instructions for both components. Qualify one declared
   OS/provider/hardware profile. Artifacts bind source and verification evidence.
   The recipient needs no private repository or copied maintainer state.
2. **Funded atomic claim:** protected sponsor setup, authoritative offer terms and
   real provider backing. Define amount, units, expiry, owner powers and cap limits.
   Concurrent first claims have one winner; retry, restart, lost acknowledgement
   and ambiguous upstream creation cannot duplicate issuance or expose another
   recipient's credential. Existing pre-bound experiments are not this acceptance.
3. **Gas without a funded wallet:** network sponsorship covers every required
   recipient transaction, including bootstrap. No gas is needed to ask for gas.
   Prefer sponsored transactions for this preview; transferable gas balances are
   not required. Off-chain steps need no invented transactions. Define finite
   sponsor budgets, exhaustion, replay and abuse controls without registration.
4. **Verified issuance and direct inference:** verify the issuing service's admitted
   code and recipient-bound encrypted delivery. Install without silently replacing
   an existing key; independently enforce provider/model admission. The sponsor
   never receives the issuance secret; verify that provider account-owner APIs
   cannot later retrieve it either. Revoke/edit powers may remain, and subsequent
   voluntary sharing by the recipient is outside that guarantee. Prompts go
   directly to the provider. No
   raw keys in logs or automatic private summaries to the outside setup agent.
5. **Understandable use and recovery:** show actual provider, credit or stale/unknown
   balance, retention and sponsor revoke/edit powers. Exercise claimed/expired
   gifts, exhausted credit, unavailable service, revoked key, interrupted claim
   and restart. Forgetting is not upstream revocation or secure erasure. Private
   diagnostics must not escape to the outside agent.
6. **Accounting and deposit outcome:** demonstrate one test-funded deposit return
   with independently verified issuance/usage evidence and the selected contract.
   Reject wrong-key, stale, corrected, replayed and unattested evidence. Pin chain,
   addresses, units, threshold, finality and unconsumed-deposit policy. A testnet
   contract is not mainnet. Additional reward economics are separate and deferred.
7. **Deployable service:** pin artifact/source/measurement, protocol, discovery,
   provider and chain configuration. Document protected provisioning, reserve
   monitoring, relay recovery, restart, compatible upgrades and safe withdrawal
   without stranding claims. Qualify an independently operated peer/client and
   report remaining privileged authority against the dsmack charter; one
   maintainer's machine alone does not demonstrate decentralization.

## Later portable-agent and node-provided VPN milestone

ProtonVPN and VPN routing are later work, not prerequisites for gift redemption
or the introductory incognito session. Incognito means sandbox and encrypted
session retention; it does not claim network anonymity. The later portable-agent
and node-provided VPN milestone must qualify discovery/installation, redemption,
RPC/gas, attestation retrieval and inference through its declared route, including
DNS, IPv4/IPv6, libp2p and fallback paths. VPN loss must fail closed. Historical
VPN experiment reports remain evidence for their original scope only.

## Final acceptance and deployment decision

Use one pinned candidate and declared bounded funds. An independent friend with
no project account or funded wallet completes the journey from public instructions
without hidden maintainer intervention. Use synthetic private content and consented,
redacted evidence. Record steps, elapsed time, friction and whether the result was
useful; agree any numeric usability target before the run, not retroactively.

The recipient walkthrough, sponsor/deposit outcome and operator recovery checks
form one release packet. Andrew reviews the actual experience and accepts it;
agents cannot infer satisfaction from test counts or concept screenshots. If
intervention is needed, fix its cause and rerun the affected scope.

Both repository milestones must show required gates complete, independent review
and linked evidence before closing. The packet must identify exactly what Andrew
can deploy, its supported scope, verification and recovery steps. Public visibility,
release publication and deployment are explicit release actions; this planning
change performs none of them. Staging qualification is distinct from a public launch.

One provider/profile is sufficient. A general market, all providers, Tails/USB
packaging, inference routing and development bounties are not dependencies.
The introductory gift session uses incognito by default. Portable-agent and
node-provided VPN support are separate later milestones.
