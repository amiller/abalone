# Abalone roadmap

Abalone focuses on useful private work, deliberate disclosure, understandable
retention and a graceful handoff from an existing agent. Prefer curated skills,
configuration and small explainable Pi changes. Dsmack service operations are a
separate responsibility.

## First milestone

Qualify one guided gift route from a public URL to useful incognito inference.
The current candidate selects Linux x86_64/Node 24 on a trusted owned host,
direct NEAR inference and a Dsmack issuer. Optional incognito is the first
introduction, not a mandatory global mode. See
[getting started](getting-started.md) and [security profiles](security.md).

The release is accepted when an independent newcomer can:

1. Find and acquire the exact reviewed helper without maintainer authentication.
2. Understand the supported host, inference destination, operator powers and
   selected trust exceptions before hidden gift entry.
3. Redeem once without a provider account, API key, funded wallet or prior pairing,
   then complete useful work with understandable pending/error states.
4. Choose session-only use or retained encrypted traces, and understand credit
   limits, close behavior and unqualified recovery.
5. Close without automatic private content returning to the setup agent.

A smoke coupon must be separate from the recipient's coupon. Record exact source,
environment, public inputs, elapsed phases, outcome and any intervention. The
owner must approve sending the URL to a friend. Local tests or one model reply
alone do not meet this outcome. The [release procedure](release.md) defines the
artifact and publication checks.

Current work is tracked in [Abalone issues](https://github.com/amiller/abalone/issues):
[status and credit](https://github.com/amiller/abalone/issues/1),

## Follow-on work

- Qualify explicit bubblewrap containment and portable setup, including actual
  route-loss behavior if network isolation is selected; see [VPN checks](vpn-qualification.md).
- Make the session's tools, destinations, retention and live credit state easy to
  understand through a real walkthrough.
- Support deliberately authorized outside work and outward artifacts without
  silently falling back to subscription inference for private reasoning.
- Develop user-selected browser integration with scoped grants and stop/control
  behavior. The current [CDP interface](protocols/browser-grant.md) does not
  establish an extension connected to an ordinary running browser profile.
- Define and qualify stronger private issuer custody, recovery, rollback and
  settlement separately from the bounded debug-staging trial. Anonymous redemption,
  portable IP isolation, pooled funding and multi-provider routing need their own
  evidence and interfaces; they are not implied by accountless claiming.
- Maintain reproducible releases, CI and documented Pi/ACI updates. Keep peer
  compatibility code together until a reviewed extraction is ready.

Source publication, installed-release qualification and a successful live user
journey remain separate. Completing this cleanup does not qualify a service,
promote a release or close these product milestones.
